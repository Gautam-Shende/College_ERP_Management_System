## 1. Overview of Changes

### Database Conversion (MySQL → PostgreSQL / Neon)
- **Database Library**: Removed `mysql2` and installed native `pg` driver with PostgreSQL connection pool.
- **SQL Syntax Conversion**:
  - `AUTO_INCREMENT` → `GENERATED BY DEFAULT AS IDENTITY`
  - MySQL `?` placeholders → PostgreSQL `$1`, `$2`, `$3` parameterized placeholders.
  - MySQL `LIKE` → PostgreSQL `ILIKE` for case-insensitive searching.
  - `ON UPDATE CURRENT_TIMESTAMP` → PostgreSQL trigger function (`update_updated_at_column()`).
  - MySQL `ENUM` → PostgreSQL `CHECK` constraints (`users.role`, `users.status`).
  - `INSERT INTO ...` → `INSERT INTO ... RETURNING id`.

### Backend Clean Architecture Refactoring
The backend was restructured from mixed models to a layered Clean Architecture:

```
server/
├── src/
│   ├── config/
│   │   ├── database.js     (Centralized pg.Pool with Neon SSL support)
│   │   └── constants.js    (HTTP status codes, messages, roles)
│   ├── queries/            (Separated SQL queries per domain)
│   │   ├── student.queries.js
│   │   ├── course.queries.js
│   │   ├── department.queries.js
│   │   ├── user.queries.js
│   │   └── dashboard.queries.js
│   ├── repositories/       (Database access layer executing pg queries)
│   │   ├── studentRepository.js
│   │   ├── courseRepository.js
│   │   ├── departmentRepository.js
│   │   ├── userRepository.js
│   │   └── dashboardRepository.js
│   ├── services/           (Business logic & domain validation)
│   │   ├── studentService.js
│   │   ├── courseService.js
│   │   ├── departmentService.js
│   │   ├── userService.js
│   │   └── dashboardService.js
│   ├── controllers/        (Thin HTTP request/response handlers)
│   │   ├── studentController.js
│   │   ├── courseController.js
│   │   ├── departmentController.js
│   │   ├── userController.js
│   │   └── dashboardController.js
│   ├── middleware/         (Auth, authorization, validation, logger, error handling)
│   │   ├── authMiddleware.js

│   └── seed.sql            (7 departments, 10 courses, 100 students seed data)

```

## 3. PostgreSQL / Neon Setup

1. Sign in to your [Neon Console](https://console.neon.tech/).
2. Click **Create Project**.
3. Name your project (e.g. `college-erp-db`), select a region close to your deployment, and click **Create Project**.
4. In your project dashboard, navigate to **Connection Details**.
5. Copy the **Connection String** (PostgreSQL URI format):
   ```
   postgresql://USER:PASSWORD@ep-xyz-123456.region.aws.neon.tech/neondb?sslmode=require
   ```

## 4. Database Migration (Schema & Seed)

You can execute the SQL scripts against Neon using the **Neon SQL Editor** in the web console, or via `psql` command line tool.

### Method A: Neon Web Console SQL Editor (Recommended)

1. Open your Neon Dashboard and navigate to the **SQL Editor** tab.
2. Open `database/schema.sql` from this repository, copy its contents, paste into the Neon SQL Editor, and click **Run**.
   - This creates `departments`, `courses`, `students`, and `users` tables, indices, triggers, and foreign keys.
3. Open `database/seed.sql` from this repository, copy its contents, paste into the Neon SQL Editor, and click **Run**.
   - This seeds **7 departments**, **10 courses**, and **100 students** with valid foreign keys.

### Method B: Command Line using `psql`

```bash
psql "postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require" -f database/schema.sql
psql "postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require" -f database/seed.sql
```

## 5. Environment Configuration (`.env`)

Do **NOT** commit real `.env` files to git. A template is provided in `server/.env.example`.

Create `server/.env`:
```env
PORT=5000
DATABASE_URL=postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require
JWT_SECRET=your_secret_jwt_key_here
CLIENT_URL=http://localhost:5173
```

Create `client/.env`:
```env
VITE_API_URL=http://localhost:5000/api
```

## 11. Deployment Instructions

### Backend (Render / Railway / Vercel Serverless)
1. Set Environment Variables on host platform:
   - `DATABASE_URL`: Neon PostgreSQL connection string (with `sslmode=require`).
   - `JWT_SECRET`: Random long string.
   - `CLIENT_URL`: Deployed frontend URL.
2. Build command: `npm install`
3. Start command: `npm start` (`node server.js`)

### Frontend (Vercel / Netlify)
1. Set Environment Variable:
   - `VITE_API_URL`: Deployed backend API base URL (e.g. `https://your-api.onrender.com/api`).
2. Build command: `npm run build`
3. Output directory: `dist`

## 12. Security & Best Practices

- **Parameterized Queries**: Used `$1`, `$2` placeholders everywhere to eliminate SQL injection risks.
- **Environment Isolation**: No real credentials or JWT secrets hardcoded in git.
- **Error Masks**: Errors returned to API consumers avoid dumping raw SQL error codes or internal database details.
- **SSL Enabled**: Neon PostgreSQL connections require SSL (`sslmode=require` / `{ rejectUnauthorized: false }`).

## 13. Manual Steps Summary

To run this application locally or in production, you only need to:
1. Create a Neon PostgreSQL database and copy the `DATABASE_URL`.
2. Run `database/schema.sql` and `database/seed.sql` on your Neon database.
3. Create `server/.env` with your `DATABASE_URL` and `JWT_SECRET`.
4. Register the first Principal user via `/api/users/register` or `/register` UI page.
